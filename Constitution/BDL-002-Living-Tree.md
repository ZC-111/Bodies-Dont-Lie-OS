## Purpose

The Living Tree is the organizational model for how Bodies Don't Lie OS grows. It describes where every piece of knowledge belongs, how layers connect, and how the system expands without becoming a book.

Where [BDL-001](BDL-001-Wayfinding-Kernel.md) defines *how* projects progress, BDL-002 defines *where* knowledge lives and *how* it grows.

---

## The Tree

```
                    🍃 Leaves — atomic knowledge objects
                   /
              🌿 Branches — domains and topics
             /
        🪵 Trunk — BDL standards (000, 001, 002…)
       /
  🌱 Roots — Constitution and principles
```

Each layer is an atomic document in [Living-Tree/](Living-Tree/).

| Layer | Role | Document |
|-------|------|----------|
| Roots | Foundational principles — slow, deep, rarely change | [01-Roots.md](Living-Tree/01-Roots.md) |
| Trunk | Operational standards — stable, referenced often | [02-Trunk.md](Living-Tree/02-Trunk.md) |
| Branches | Domain organization — grows as fields emerge | [03-Branches.md](Living-Tree/03-Branches.md) |
| Leaves | Atomic knowledge — one idea, one file | [04-Leaves.md](Living-Tree/04-Leaves.md) |
| Growth | Rules for adding without bloating | [05-Growth.md](Living-Tree/05-Growth.md) |
| Pruning | Rules for reducing through reflection | [06-Pruning.md](Living-Tree/06-Pruning.md) |

---

## Rules

1. **Knowledge grows at the leaves.** Add new files; do not enlarge existing ones.
2. **Link, don't duplicate.** If it exists elsewhere, link to it.
3. **Branches emerge from need.** Do not pre-build domain folders before content exists.
4. **Prune regularly.** Every reflection cycle asks: can this be removed or merged?

---

## Non-Goals

The Living Tree does **not**:

- Prescribe a fixed taxonomy of domains before they emerge
- Require every project to fill every branch
- Optimize for folder count or tree depth
