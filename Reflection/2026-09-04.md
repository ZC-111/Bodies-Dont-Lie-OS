## What happened

Graduated the Lung channel (LU-1…LU-11) into `Knowledge/` leaves across three passes:

1. **Pass 1** confirmed 5 points from extract fields alone.
2. **Pass 2** found the extract's clinical fields were **contaminated** (LU-6/LU-9 carried LU-8's indications; LU-1 was wrong). Fixed the extractor's cluster propagation and re-verified against the source.
3. **Pass 3** added a **column-aware page reader** for the two-column layout, which caught a further boundary error (LU-5's indications began with LU-4's) and recovered the two deferred points. Result: the full channel, 11/11, each field read from the source.

## What we learned

1. **Extraction is not confirmation, and "non-empty" is not "correct."** Two published leaves were wrong; only reading the gold-standard source caught it. Health-domain claims are now cited to the exact Deadman page each field was read from.
2. **The contamination bug: landmark references were mistaken for shared clinical blocks.** `propagate_cluster_fields` copied clinical sections between points that name each other in *location* prose. Fixed: clinical sections are never propagated; only a missing location may be shared, and it is flagged.
3. **Layout is the root cause; column-aware reading is the right primitive.** pypdf's default extraction reads across both columns, scrambling and interleaving points. Reconstructing reading order per column (`deadman_extract.py --page N`) yields correct per-point sections and resolved every remaining ambiguity.
4. **A correct primitive is not a safe drop-in.** Swapping column-aware text into the extractor's global path *regressed* the heuristic parser (`classical_with_full_text` 357 → 301): header/section detection was tuned to the scrambled text. Shipping that to a health dataset would trade known-good rows for silent regressions. So the global migration is deferred behind a header-detection rewrite + book-wide re-validation; per-point column-aware reading is used meanwhile.
5. **Validation gates must test the right property.** The gate moved from "field non-empty" → "field is the point's own, source-verified text."

## Reflection questions

- *Is this still true?* Three corrections were made and recorded openly, not silently overwritten.
- *Can this be expressed more simply?* Leaves link to the dataset and cite source pages instead of copying the corpus.

## Loops back to

- **Build:** migrate the extractor to column-aware parsing — the payoff (correct per-point attribution for every channel) is large, but it needs robust header detection for OCR-corrupted/multi-page headers and full re-validation before it can replace the current parser.
- **Observe:** the contamination pattern touched ~50 points across other channels; audit each channel against the column-aware source before graduating — do not trust extract fields alone.
